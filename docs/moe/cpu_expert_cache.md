# 可逆编码路径的 CPU 专家缓存

## 分配与数据路径

`weight_encoding=lattice` 的 AIO/NVMe 后端先将编码载荷读入 SPDK DMA
暂存区，再由 CPU 解码写入专家缓存。专家缓存使用普通 CPU 内存，不作为
DMA 目标。缓存按 2 MiB 对齐，向内核请求 `MADV_HUGEPAGE`，启动时清零并
预触碰所有有效权重页；THP 是建议，普通页仍可正确运行。

每个专家仍保持一块虚拟连续的 168 MiB FP32 缓存，Gate/Up/Down 指针及
计算顺序不变。8 槽共 1344 MiB；分配和首次写入发生在 reactor 上，正式
入口优先选择 NVMe 所在 NUMA 节点。实际 THP 覆盖由 `AnonHugePages` 监测。

SPDK 默认固定 HugeTLB 池改为 256 MiB，即 128 张 2 MiB 页，仅供 SPDK
对象池、编码 DMA 暂存区等使用。它与 CPU 专家缓存分别占用内存，合计
1600 MiB，此外还必须计入进程堆栈、工作区、索引等。总预算按官方限制
验收，不能仅凭两个已知分配项断言通过。分配完成后执行 16 次内部预热，
通过后才发布服务。

正式入口在框架初始化之前设置 iobuf：1024 个 8 KiB 小缓冲、256 个
132 KiB 大缓冲，共 41 MiB 数据区。TCP 配置 128 个共享缓冲、每轮询组
缓存 32 个，避免沿用面向通用工作负载的大池默认值。这些缓冲与专家
权重读取的 1 MiB 编码暂存区不同，不改变权重 I/O 粒度。

非编码路径继续使用 SPDK DMA 专家缓存，因为原始权重 I/O 直接写入缓存；
完整尺寸 raw 调试需要显式设置足够的 SPDK 池，不能套用编码模式的 256 MiB。
编码内的原始字节回退块仍经编码暂存区解码/复制到 CPU 缓存。

## I/O 与计算边界

保持原有 1 MiB 逻辑编码块、4 个在途 I/O 和矩阵 FIFO。I/O 完成并解码成功
后才发布就绪范围；DMA 缓冲在解码完成后复用。正在读取或计算的专家槽位
保持引用，不可淘汰。计算切片大小不决定内存分配大小。

## 验证与产物

`run_target.py --dry-run` 显示 256 MiB / 128 页。正式入口的
`bdev_get_bdevs` 必须报告 `cache_memory=cpu` 和 `warmup_completed=16`，
否则不会建立监听。裸金属测试使用正式提交补丁构建，保留启动日志、独立
参考正确性结果、预热后 50 次延迟及 CPU/内存采样。资源采样需同时统计
RSS 和去重后的 HugeTLB，并单独报告 THP，避免重复计费。

回归覆盖 CPU 缓存对齐、数值结果、编码和 raw I/O 路径，以及启动分配失败
降槽重试。运行方法沿用 `reversible_weights.md` 中的流水线测试命令。
