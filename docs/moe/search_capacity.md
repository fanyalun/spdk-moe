# 编码路径的参数搜索上限

默认仍为 8 个专家槽位、I/O 深度 4、1MiB 逻辑块、256MiB SPDK DMA 池。新增范围用于后续实验，不宣称参数越大越快。

原生 NVMe 粗筛中，深度 16 的两轮 P99 为 384.023356/385.165463ms，低于深度 8 的 443.494513/446.503018ms。最优点仍在原实现上界，因此将 `MOE_STORE_MAX_IO` 从 16 扩展到 64，支持继续比较 32、64，并在同一新构建中复测 16 作为对照。

在途操作数组和编码 DMA 缓冲区均按此上限或实际深度分配。DMA 缓冲区仍从既有 SPDK 池中取得；不会自动扩池。实际分配及推理峰值必须验证，不能仅凭固定池大小认定更大队列可用。

编码路径同时允许第 9 个解码专家槽位。缓存条目本身按容量动态分配，Top-K 仍为 8。原始权重路径保留最多 8 槽位，避免把编码 CPU 缓存的预算用于大块 DMA 分配。

编码缓存准入按生产入口的 256MiB 固定池估计：

```text
解码缓存字节数 + 129MiB CPU 运行预留 + 256MiB DMA 池 <= 2,000,000,000 bytes
```

正式尺寸的 9 个槽位占 1512MiB，以上估计合计 1897MiB。此准入估计不能代替 cgroup 或外部峰值监测；使用其他 DMA 池大小的开发入口也须独立核算总内存。

```sh
python3 run_target.py --dry-run --cache-slots 9
```

已有 pipeline 测试增加了仅用于所选正常 FIFO 案例的覆盖项，可用宽矩阵触发超过 16 个在途块：

```sh
make -C test/moe/tile_progress -j2
MOE_TEST_WIDE=1 MOE_TEST_FIFO=1 MOE_TEST_ENCODING=lattice \
  MOE_TEST_LATTICE_WEIGHTS=1 MOE_TEST_CASE= MOE_TEST_STARTUP_WARMUP=16 \
  MOE_TEST_CACHE_SLOTS=9 MOE_TEST_IO_DEPTH=64 \
  python3 test/moe/test_moe_pipeline.py
```

该测试比较独立参考输出、完整布局和启动预热顺序；正式尺寸原生 NVMe 的内存及性能仍需单独验证。

在裸金属的独立构建副本上，该配置通过 32 个正常请求的独立参考比较，最大绝对误差为 0。另以 `MOE_TEST_STARTUP_WARMUP=0` 运行仅用于正确性覆盖的冷启动用例，实际峰值为 48 个在途 I/O，32 个正常请求同样误差为 0；两个用例均通过预期的非法输入拒绝检查。冷用例不参与性能排名。原 V3 二进制未被替换，深度 32/64 与 9 槽位尚无正式尺寸原生性能成绩。

实际原生测试应先按提交指示准备独占 NVMe、2MiB 大页及原始权重，再通过测试配置分别改变深度或槽位。每个候选执行完整预热、严格 `<1e-5` 的独立正确性校验及两轮各 50 次计时，并计入 RSS、去重 HugeTLB 和启动器开销。第 9 槽位及更大深度的性能、内存结果尚待验证。
