# 可逆编码实测：2026-10-13

## 条件与输入一致性

本机为 Xeon Gold 6248，Samsung MZQLB7T6HALA，PCIe Gen3 x4。
使用 Linux AIO O_DIRECT 文件模拟权重设备，非官方原生 NVMe 环境。
官方说明为 Xeon Silver 4214、单 NVMe 标称 7000 MB/s、2 GB 总内存约束。
因此以下数值描述本机实验，不能直接推断官方 P99。

实际维度为 2048/7168、256 专家、Top-8；AVX2、计算线程 1、I/O 深度 4、
逻辑分块 1 MiB、八缓存槽位、矩阵 FIFO。关闭诊断；六轮 CPU throttling
增量均为 0。每轮重新启动并导入镜像，预热 16 次（seed 777），随后计时
50 次（seed 42）。正确性验证另用 seed 4242。

六轮计时使用相同的 50 个输入，完整序列摘要均为：

```text
43a9cf71806febceb37e470e364ca03ad03b03734d91bbfdf6ccf8e3106d98a8
```

P99 使用最近秩 `ceil(0.99 * 50)`，即该轮最大值，不剔除异常请求。
三组结果如下；实际运行顺序为原始 1、编码 1、编码 2、原始 2、原始 3、编码 3。

| 轮次 | 原始 P99 / ms | 可逆编码 P99 / ms |
| --- | ---: | ---: |
| 1 | 448.530 | 651.495 |
| 2 | 457.257 | 364.505 |
| 3 | 447.983 | 364.751 |

编码第一轮第 7 个计时请求为 651.495 ms，原因尚未定位，可能是偶发波动。
该轮 P50 为 364.456 ms；后两轮 P99 接近 365 ms。
三轮各自 P99 的中位数由 448.530 降到 364.751 ms，降幅 18.68%。
这只是重复实验对比指标，不是合并请求后的 P99，也不是官方成绩。

## 全权重与输出正确性

原始专家矩阵共 45,097,156,608 字节，43,008 个块全部逐字节往返一致。
其中 43,005 块使用 25 位，3 块使用 26 位，无原始回退块。
按 512 字节对齐后的读取载荷为 35,232,251,904 字节，即原始的
78.125218%，**减少 21.874782% 读取字节**。元数据另占约 1 MiB 的头区域。
逻辑偏移与间距保留，镜像文件仍为 45,100,302,336 字节。

正式实验写出的版本 2 镜像又全量读回解码，恢复的专家矩阵 SHA-256
与原始专家矩阵相同：

```text
e7cad018b70e48c959d962d1f82a64a3bd98a747968317afeb95e03c096c17ba
```

编码首轮通过独立 TCP 发起器检查 50 个输入，最大绝对误差全部为 0；
其他五轮各检查一个输入，同样为 0。使用赛题严格 `<1e-5f` 阈值。
小矩阵另验证三个独立权重种子，每组 50 个不同输入；检查缓存命中、
多个计算线程、读取失败、设备移除、取消、shutdown、损坏权重恢复。
普通浮点权重的原始回退和 ASAN/UBSAN 编码单元测试也通过。
这不代表已经验收官方隐藏权重或官方 cgroup 内存。

## 成本与限制

全量原生解码函数计时约 9.43 GB/s，包含校验，但复用暖缓冲区；
不包含 SSD 读取和完整推理流水线的内存流量。
盘上验证的对应值约 9.45 GB/s，同样仅累计解码函数时间。
导入约 288–291 秒，原始导入约 64–65 秒。
本机 owner/reactor 与导入线程共享 CPU，初始化 CPU 调度影响该成本。

本地使用 1664 MiB SPDK no-huge 预留，编码 target 最大 HWM 为
1,498,352 KiB，较原始多约 5 MiB。该测量不等同于官方包含 hugepage 的
2 GB cgroup 验收。缓存保存 FP32，编码不会提升缓存命中率。

按用户决定默认启用编码，同时保留 `weight_encoding=raw`。
首轮尖峰保留在结果中；官方性能及内存验收待对应设备验证。

本地原始日志目录：`/root/moe-run-logs/reversible_20261013/`。
包含 `full_verification.json`、`stored_verification.json`、`p99/results.json`、
每轮请求 JSONL、正确性日志和默认启用路径测试日志。
