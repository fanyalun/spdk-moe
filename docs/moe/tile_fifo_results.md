# 细粒度流水线粗筛结果

## 配置与 P99

本地 Xeon Gold 6248、Samsung MZQLB7T6HALA、Linux AIO O_DIRECT，非官方
Xeon Silver 4214 的原生 NVMe 环境。实际维度为 2048/7168、256 专家、Top-8。
每个配置重新导入同一授权实验镜像；缓存八槽位，AVX2，一个计算线程，
1 MiB 编码块、I/O 深度 4。没有修改编码算法、盘上版本 2 布局或 SIMD 宽度。
正式计时关闭 NVTX 和诊断。

每轮 16 次预热，seed 777；随后 50 次计时，seed 42。所有输入摘要均为：

```text
43a9cf71806febceb37e470e364ca03ad03b03734d91bbfdf6ccf8e3106d98a8
```

P99 使用 `ceil(0.99 * 50)`，即该轮最大值，不剔除异常请求。
CPU throttling 增量均为 0。

| 模式 / 计算任务通道上限 | P99 / ms | P50 / ms |
| --- | ---: | ---: |
| 矩阵 FIFO 基线 | 370.277 | 352.548 |
| 细粒度 64 | 439.216 | 415.544 |
| 细粒度 128 | 388.742 | 361.426 |
| 细粒度 256 | 366.248 | 345.693 |
| 细粒度 512 | 344.838 | 342.655 |

本轮 512 上限最好，P99 比基线低约 6.87%；64 上限反而高约 18.62%。
这只是一次粗筛，每个配置 50 样本，没有证明跨轮稳定收益、官方收益或
全局最优。此前矩阵 FIFO 编码路径也出现过约 365 ms 的 P99。
新模式显式启用时默认任务上限设为 512，生产默认模式仍是矩阵 FIFO。

64 是内部 SIMD/存储组宽度；表中 64–512 是一次任务的最大输出通道数量。
实际任务可能因已就绪数据较少而小于上限，命中专家走原完整计算快速路径。
因此这些结果不等于比较了 32/64/128 的 SIMD 内核宽度。

## 正确性与机制验证

- 新分块内核在所有本机支持的 scalar、AVX2、AVX512 上，以 64/128/256/512
  任务范围执行，Gate、Up、Down 与整矩阵算法逐位一致，ASAN/UBSAN 通过。
- I/O 单元测试强制乱序完成：先发布 1 MiB，后续第三块先完成不推进，再补齐
  第二块发布 3 MiB，最后发布 4 MiB，确认计算不必等待整矩阵读完。
- 集成测试覆盖三个权重种子、多种任务上限、2/4 个计算线程、部分 Down
  输出复制、命中、取消、移除、shutdown、坏权重、原始格式及原始回退。
- 独立跨块测试使用 128×4096 权重及受限读速。首个 miss 专家的 Gate、Up、
  Down 分别在矩阵读取完成前约 31.63、39.69、41.01 ms 开始计算。
  这验证依赖关系，不能当作正式性能加速量。
- 64 上限在官方尺寸上另用 seed 4242 做 50 个独立 TCP 参考比对，误差均为 0；
  基线及 128/256/512 的各一次比对也均为 0。阈值严格为 `<1e-5f`。
- 512 上限在新 Nsight 采集后另做了 50 个独立参考输入比对，误差均为 0。

小粒度可能增加计算任务与协调成本。八专家全 miss 时，64 上限会拆出
2048 个计算任务，原矩阵阶段至多 24 个；不能仅凭早点开始就推断 P99 更好。
具体 CPU/等待分解应使用原生 NVTX 的区间并集，不能把阶段首尾 envelope
当作连续计算时间。

## 512 上限的原生流水线报告

报告位于 `nsys_tile512/moe_cpu_experts_io_decode.nsys-rep`，保留原始 CPU 线程、
异步 I/O、Decode 和等待标记，并为每个计算块增加实际 `channels=first..last`。
检查每个专家的 Gate/Up/Down 通道范围无缺口、无重复，50 个请求全部通过。

原生采集平均每请求 666.78 个计算任务，计算区间并集 144.05 ms，解码
281.04 ms，二者同时执行 135.89 ms。二者并集 289.21 ms，落在未完成 I/O
之外约 0.48 ms，覆盖比例约 99.83%。这是软件时间重叠，不代表 SSD 持续
传输或解码无成本。模型执行仍为 CPU AVX2，没有 GPU 轨道。

50 个计时请求共 393 个 miss 专家，其中 Gate/Up/Down 分别有 386/392/392
次在其整矩阵读取完成前开始计算。命中专家仍走原快速路径。
采集首尾请求包含 profiler 开关开销，不能使用这批 TCP P99 评分。
本机未运行 Nsight GUI；原生报告和导出事件已验证。GUI 打开步骤与旧报告相同，
见 [Nsight README](../../test/moe/nsys/README.md)。
